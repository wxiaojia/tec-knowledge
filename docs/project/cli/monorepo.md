# 【初中级】你的过往项目中，项目和工程化架构有没有做过，有没有了解过 monorepo 架构方案?
- 做过，组件库，脚手架

## 传统项目概述
- 独立项目结构，所有项目都是分开的github仓库（如之前的组件库gendo-ui和gendo-shared）
- 技术栈独立
- 规范化、自动化相关处理是割裂的
- 依赖管理，版本关系 很难统一管理
- 部署，docker docker-compose, 自动化脚本 很难统一


## monorepo
- 单一代码仓库：混合项目结构，所有相关工程形成子包进行管理
- 技术栈统一 ，（团队基建项目，业务项目，子服务）
- 统一构建发布：规范化、自动化、流程化，项目共享
- 统一管理依赖：依赖管理，版本统一管理
- 部署，docker docker-compose, 自动化脚本统一部署流程

## monorepo 架构方案
- 包管理，pnpm workspace、yarn workspace、lerna
- 构建缓存
- 增量构建，nx、turbo

## pnpm 优势
- 软链接，在集中的地方安装，通过寻址的方式找到依赖的具体位置（多包管理，资源共享，中心化思想）使用符号链接代替直接安装，减少重复的依赖安装。​
- 缓存，PNPM 的缓存机制使得安装依赖速度更快。​
- 原生支持Monorepo：支持工作空间（Workspaces）配置，方便子包间依赖管理。​
- 磁盘占用少：通过去重机制大幅减少磁盘使用量。

！！！中心化思想，解决依赖复用问题
