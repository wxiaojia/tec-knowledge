1. 上传文件的整体流程
主要包含以下几个步骤：

获取上传地址

上传文件或分片

更新文件上传状态（进度、成功、失败）

上传任务完成后执行回调或其他任务

2. 上传文件的工作流程
代码中有多个核心函数来实现文件的上传功能，以下是各个步骤的详细说明：

(1) 文件上传接口 uploadFile
该函数是文件上传的主要入口，支持单文件上传、分片上传、以及批量上传。

步骤：

初始化文件数据：检查上传文件的大小，初始化上传相关信息（key、bucketName、fileName等）。

判断文件大小：如果文件小于设定的分片大小（CHUNK_SIZE），直接进行单文件上传。否则，进行分片上传。

上传文件：通过调用不同的上传方法（如uploadPutObject和multipartUpload）来执行具体的上传任务。

(2) 单文件上传 uploadPutObject
如果文件小于分片大小，使用此函数进行单文件上传。

步骤：

获取上传地址：通过uploadApi.presignedPutObject获取上传的预签名URL。

执行上传：调用putFile函数将文件上传到指定的URL。

上传成功：上传成功后，调用success函数更新上传状态，并传递上传成功的信息。

上传失败：如果上传过程中出现错误，调用error函数更新状态为失败并显示错误信息。

(3) 分片上传 multipartUpload
当文件超过设定的分片大小时，会进行分片上传。

步骤：

获取分片信息：首先检查文件是否已经存在上传记录（如分片上传ID）。如果没有，调用API创建一个新的上传任务。

生成分片文件：将大文件分割成多个小分片（chunkList）。

上传分片：逐个上传分片，每个分片上传之前会获取上传地址，然后使用putFile函数上传。

更新进度：每上传一个分片，就更新文件的上传进度。

上传完成：所有分片上传完成后，调用API完成分片上传，合并所有分片。

上传失败：如果在上传过程中出现错误，更新上传状态并返回失败信息。

(4) 批量上传 uploadFileList
该函数支持批量文件上传，它会依次上传每个文件。

步骤：

初始化上传数据：计算所有文件的总大小并初始化状态。

逐个上传文件：依次上传文件，调用uploadFile方法上传每个文件。

上传成功或失败：每个文件上传后会更新上传状态，并执行相关的回调函数。

执行任务：上传成功后，可以执行相关任务（如调用successRunTask）。

(5) 更新上传进度 updateProgress
每上传一定数据量，就会调用此函数来更新文件上传的进度。

步骤：

计算进度：计算已上传的数据量占总数据量的百分比。

更新状态：更新文件的上传状态（进度、已上传的字节数等）。

(6) 更新文件和任务数据 updateListData
用于更新文件在上传列表中的状态。

步骤：

初始化文件数据：如果是第一次上传，会初始化文件的进度和状态。

更新进度和状态：根据上传的字节数更新进度，标记文件上传的成功或失败。

3. 任务处理和回调
在文件上传过程中，回调函数用于通知外部任务（例如上传成功后需要执行的任务）。

任务执行：使用addTask方法把任务添加到上传任务列表中，通过runTask方法执行任务。

4. 上传成功和失败的处理
成功：上传成功后，会调用success函数，更新上传状态为“上传成功”，并通知回调函数。

失败：如果上传失败，会调用error函数，更新上传状态为“上传失败”，并显示错误信息。

5. 分片上传的进度管理
上传分片时，通过updateProgress函数实时更新进度信息。

在上传过程中，如果用户取消上传，系统会通过标志位isStop来终止上传。



### 具体流程：
- 开始上传：触发上传流程的开始。

- 初始化文件数据：为上传的文件初始化相关信息（如文件大小、上传状态等）。

- 判断文件大小：根据文件大小判断是否需要分片上传。

    - 如果文件小于分片大小，则进入小文件上传流程。

    - 如果文件大于分片大小，则进入分片上传流程。

- 获取上传地址：获取文件上传的预签名URL。

- 执行上传：使用获取的上传地址执行文件上传操作。

- 上传成功/失败：

    - 上传成功后更新进度，并调用成功的回调。

    - 上传失败时，更新进度并调用失败的回调。

- 更新上传进度：实时更新文件上传的进度。

- 任务执行：上传完成后执行额外的任务。
