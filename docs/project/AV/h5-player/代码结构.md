## 项目核心功能
- 多协议支持：支持 RTSP、RTMP 和 HTTP (MP4) 流的接入与播放。
- 双解码机制：
  - 硬解码 (MSE)：通过 wfs (Web Flow Segment) 模块利用浏览器的 Media Source Extensions 进行硬件加速解码（如 H.264）。
  - 软解码 (Wasm)：对于浏览器原生不支持的编码格式，通过集成 FFmpeg (WebAssembly) 进行软件解码。
- 高性能渲染：
  - 视频：支持 Canvas 和 WebGL 渲染。
  - 音频：支持 PCM 音频播放。
- 多线程处理：大量使用 Web Workers 处理 WebSocket 通讯、视频流解析、FFmpeg 解码和 MP4 转封装，确保主线程流畅，不卡顿。
- 健壮性监控：内置 health-checker.js 心跳检查机制，能够自动处理连接异常、超时及播放器重启。

## 播放流程详细步骤解析：
1、数据接入 (Websocket Worker)：
    - 为了不阻塞主线程，播放器在后台开启 websocket.worker.js。
    - 它负责建立 WebSocket 连接，持续接收来自服务端的二进制流数据。
2、协议解包 (Protocol Parsing)：
    - 接收到的数据经过 rtsp/ 或 rtmp/ 模块解析。
    - 解析器从复杂的协议包中提取出视频的原始负载（如 H.264 的 NALU 单元）。
3、智能分流 (PlayLoader & Codec Check)：
    - PlayLoader 接收到流信息（SDP）后，会判断当前浏览器是否支持该编码格式。
    - 如果支持 (MSE路径)：走“硬解”路线。
    - 如果不支持 (Wasm路径)：走“软解”路线。
4、硬解码路径 (WFS/MSE)：
    - 由于浏览器 <video> 标签不直接识别原始流，MP4-Remuxer 会将流实时包装成 fMP4 (fragmented MP4) 格式。
    - 通过 Media Source Extensions (MSE) API 将打包好的数据塞给浏览器引擎，利用显卡硬件进行解码播放。
5、软解码路径 (FFmpeg/Wasm)：
    - 利用编译成 WebAssembly 的 ffmpeg-lib.js 在 ffmpeg.worker.js 线程中进行纯 CPU 计算解码。
    - 解码后得到原始的视频帧（YUV 数据），再通过 webgl-player.js 利用 WebGL 将其渲染到 <canvas> 上。
    - 音频部分则提取出 PCM 数据，交给 pcm-player.js 播放。
6、健康监控 (Health Checker)：
    - 在播放过程中，HealthChecker 会监控 frameCount（帧率）和连接状态。
    - 如果发现长时间没收到数据或解码异常，会触发 PLAYER_REBOOT 事件，自动尝试重新连接和初始化。
